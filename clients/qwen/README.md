# Qwen Desktop: локальный адаптер авторизации

Этот каталог относится к **LeonidYasin/mcp-rooms**, не к старому mcp-server.
В нём сохранены те же mcp_proxy_v2.py и check_rooms_proxy.py, которые были выданы
в архиве в ходе реального Qwen ↔ Notion теста. Оригинальные байты скриптов сохранены.
Настоящих .env, ключей, пользовательских логов, БД или установщика Qwen здесь НЕТ.
Это клиентская утилита, не сервер комнат и не production gateway.

## Зачем

В разобранной сборке Qwen Desktop по адресу
https://download.qwen.ai/windows/x64/Qwen-1.0.3.44-release-win-x64.exe
библиотека @ali/spark-mcp создавала HTTP-транспорт без передачи headers. Операторский
перехват подтвердил отсутствие Authorization. Это не общая характеристика всех
Qwen и не документация Qwen Code CLI. Обоснование: ../../docs/qwen-client.md.

```text
Qwen (без секрета в конфигурации)
  → http://127.0.0.1:8790/mcp
  → локальный mcp_proxy_v2.py добавляет Bearer из .env
  → HTTPS с проверкой сертификата
  → Rooms MCP
```

## Что здесь

- mcp_proxy_v2.py — многосерверный loopback-прокси с безопасным --debug.
- check_rooms_proxy.py — initialize / initialized / tools/list, без комнатных записей.
- .env.example — ТОЛЬКО заглушка; скопируйте её в .env на своём ПК.
- qwen-local.json — JSON без ключа для добавления подключения.
- requirements.txt — зависимости только клиентской утилиты.
- SHA256SUMS.txt — контрольные суммы двух сохранённых скриптов.

.env, .env.*, токены и базы исключены из Git; исключение только для этого .env.example.
Указанный /rooms-test upstream после завершения теста **закрыт**. Запуск локального
прокси не открывает VPS и не продлевает окно. Для нового теста нужна отдельная
операторская процедура. Не включайте старый unit/регистрацию автоматически.

## Установка (Windows, Git Bash)

Перейдите в clients/qwen в своём checkout. Если зависимости уже установлены и ваш
прокси работал, повторная установка не нужна. Для нового окружения:

```bash
python -m venv .venv
. .venv/Scripts/activate
python -m pip install -r requirements.txt
```

Если команда python отсутствует, используйте py -3 для создания venv.
Windows поддерживается здесь как клиент; сам сервер Rooms рассчитан на Linux/POSIX.

Если .env ещё нет:

```bash
cp -n .env.example .env
```

Если он уже существует, НЕ заменяйте файл: добавьте/обновите только секцию ROOMS.
В .env локально подставьте свой полный ключ rm1_...:

```dotenv
ROOMS_UPSTREAM=https://leonid-mcp.duckdns.org/rooms-test/mcp
ROOMS_HEADERS="Authorization=Bearer REPLACE_LOCALLY_WITH_CHECKED_rm1_KEY"
ROOMS_PORT=8790
```

Формат заголовка именно `Authorization=Bearer ...`: один пробел после Bearer,
сам префикс Bearer не дублировать. Ни ключ, ни заполненный .env не присылайте в чат,
issue, скриншот или комнату. Защитите файл правами Windows; он хранит действующий секрет.
Для другого upstream используйте точный канонический HTTPS URL, без токенов в URL.

## Запуск

```bash
python mcp_proxy_v2.py --server rooms --debug
```

Если хотите заменить прежний процесс целиком и обслуживать все секции .env:

```bash
python mcp_proxy_v2.py --server all --debug
```

Не запускайте all поверх работающего экземпляра на тех же портах. По прежним
правилам при занятом ручном порте выбирается другой свободный: смотрите ФАКТИЧЕСКИЙ
адрес в баннере и используйте его в Qwen и проверке. Остановка — Ctrl+C.
.env по умолчанию читается из текущей папки, не из произвольного каталога скрипта.
При необходимости задайте `--env /путь/к/.env`.

Во второй вкладке Git Bash, пока upstream доступен:

```bash
python check_rooms_proxy.py --url http://127.0.0.1:8790/mcp
```

Ожидается initialize200, initialized202, tools/list200, ROOM_TOOLS=8,
PASS_LOCAL_PROXY_MCP. До успеха проверки не меняйте повторно ключи и настройки Qwen.
Если порт изменился — замените его и здесь. Этот check специально проверяет ровно
восемь инструментов текущего alpha; при будущем расширении API нужна новая версия
проверки, а не объявление любого несовпадения ошибкой авторизации.

## Qwen

Добавьте тип StreamableHTTP, адрес http://127.0.0.1:8790/mcp (фактический порт).
В форме нет необходимости вводить ключ. При JSON-добавлении используйте qwen-local.json.
Выключите дублирующее прямое HTTPS-подключение только этого Rooms, не остальные MCP.
Попросите реальный rooms_list без записи. Пустой список допустим.

Не путайте ответ агента с необработанным результатом инструмента: во время последней
проверки Qwen назвал верный ID, но изменил фактический текст. Это расхождение, а не
точно подтверждённое чтение; оно описано в ../../docs/acceptance-2026-10-19.md.

## Debug и безопасность

--debug НЕ включает Flask debugger/reloader. Видны request_id, метод HTTP,
разрешённое имя метода MCP/инструмента, факт статической авторизации, статус, время.
Не печатаются значения ключей/cookies/session-id, параметры инструментов, тела
сообщений или сырые ошибки. Имена неизвестных методов/инструментов — other.
client_authorization_present=false для Qwen нормально: важен следующий
static_authorization_present=true. Корректный формат токена ещё не доказывает вход.

- Привязка только 127.0.0.1. Нельзя публиковать этот Flask development server наружу.
- Другие процессы на ПК могут обращаться с правами настроенного ключа.
- Не используйте общий ключ с лишними правами; останавливайте адаптер после теста.
- Ответ plain Unauthorized может быть отказом старого маршрута Caddy после закрытия
  окна; JSON invalid_token — отказ Bearer приложения. 502 требует проверки upstream.
- Редиректы upstream не выполняются: 502/upstream_redirect_blocked; укажите сразу
  канонический URL. TLS не отключается.
- Запрос до 64 KiB, обычный JSON-ответ до 4 MiB. Для других MCP с большими payload
  это ограничение может быть несовместимо. SSE закрывает upstream при завершении.
- В сборке Qwen найден console.log(config): старые логи могут содержать конфигурацию.
  Никогда не публикуйте полные логи. Ротация — только после проверки замены, не отзыв
  единственного рабочего ключа.

CI проверяет этот код на Linux с Flask test client и подменённым upstream, без
сетевых вызовов/ключей/VPS. Это не сертификация Windows/Qwen GUI или production audit.
Утилита не входит в runtime-зависимости сервера Rooms и не запускается при импорте
его пакета. Проверяйте лицензии и версии зависимостей перед production-применением.

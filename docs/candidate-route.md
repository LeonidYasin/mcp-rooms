# Кандидатный HTTPS-маршрут — инструмент (подготовлен, не запускался)

`tools/operator_route.py` — узкий операторский инструмент для одного маршрута
`https://leonid-mcp.duckdns.org/rooms/*` → `127.0.0.1:8766`. Он не устанавливает,
не запускает, не включает в boot и не перезапускает сервисы, не редактирует
Caddyfile, не перезаписывает конфигурацию целиком и не трогает другие маршруты.

Статус: код и чистые тесты в репозитории; на VPS **не выполнялся**. Запуск — только
владелец на root-консоли после отдельного одобрения и специального пароля.

## Что делает

| Действие | Эффект |
| --- | --- |
| `--plan` | read-only: печатает точный JSON маршрута, маркер и размеры конфигурации до/после |
| `--open` | один условный `PUT` своего маршрута с `ETag/If-Match` |
| `--remove` | один условный `DELETE` **только** своего маршрута по уникальному маркеру |

Маршрут детерминированно помечен `mcp-rooms-candidate-<sha[:16]>`, поэтому уборка не
требует скрытого state-файла и идемпотентна: повторный `--remove` возвращает
`absent`, а не ошибку.

## Форма маршрута

- хост ровно `leonid-mcp.duckdns.org`, пути `"/rooms"` и `"/rooms/*"`;
- `Host` сохраняется, приложение проверяет его по canonical resource;
- внутрь кандидата проходят только: `POST /rooms/mcp`, `GET|POST|DELETE` для
  `/rooms/identity`, `/rooms/credentials`, `/rooms/credentials/current`,
  `GET /rooms/market` и `/rooms/market/*`;
- префикс `/rooms` срезается только на этом маршруте (`strip_path_prefix`);
- всё остальное под `/rooms` отдаёт `404` с `no-store`;
- лимит тела 64 KiB, таймауты dial/response/read/write, не более 8 соединений
  к upstream. Это не rate limit и не защита от DoS;
- никакой authentication-обвязки: ключ по-прежнему проверяет само приложение.

## Отказы (fail closed)

Инструмент останавливается с кодом, если: конфигурация без `ETag`; не ровно один
HTTPS-сервер для хоста; для хоста больше одного маршрута или он не `terminal`;
нет слушателя `:443`; префикс `/rooms` уже используется другим маршрутом; маркер уже
присутствует (для `--open`) или отсутствует/изменён/не уникален (для `--remove`);
ответ Caddy не подтверждает вставку или удаление; конфликт `ETag` (повтор с новым
чтением, не перезапись). Мутация никогда не применяется по устаревшему `ETag`.

## Порядок для владельца

1. `--plan --source-sha <db32c6d…>` — прочитать JSON и убедиться, что это ровно
   ожидаемый маршрут; эффектов нет.
2. Отдельное одобрение + пароль; затем `--open --source-sha … --authorization …`
   (фраза-подтверждение в коде инструмента, не секрет).
3. Внешние проверки по [чеклисту](https-external-checklist.md): без токена `401`,
   неизвестный путь `404`, карточка/фото `200`, withdraw → `404`.
4. `--remove` — только свой маршрут; проверить, что внешний `/rooms/mcp` больше не
   доходит до кандидата. Затем `operator_control.py stop`.

## Границы

Маршрут не делает сервис продакшном: unit остаётся временным, пока отдельно не
принят persistent-режим с boot-enable; нет backup/restore, мониторинга, реальных
ключей и решения о release. Каждый серверный шаг — отдельное разрешение владельца
и специальный пароль; CI-тесты здесь чистые и не трогают Caddy/systemd/сеть.

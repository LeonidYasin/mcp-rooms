## Scope of proof

Temporary synthetic identities/listing scopes and generated bytes only. Tests cover:

- Opt-in additive media schema, idempotent initialization, preserved room identifiers,
  SQLite integrity/FKs and reopened private media reads.
- Foreign-owner denial, revoked/disabled/expired credentials, scope loss, forged
  principal and wrong audience; audience also persisted in the media manifest.
- Revocation after file write, and revocation/archive/revision/category/expiry
  changes during decoding prevent a STAGED commit. Work does not hold a write tx.
- Read authorization after filesystem I/O, corrupt bytes and replay integrity checks.
- Same command replays without worker/file duplication or extending expiry; changed
  byte/MIME digest conflicts; concurrent pending retry does not start another worker.
- Terminal processing failure, expiry, count/byte admission budgets, no implicit
  migration and refusal of partial/future media schema.
- Real generated PNG → installed subprocess worker → durable private file →
  owner-authorized SQLite STAGED manifest → checked JPEG read.
- Draft APIs still reject media_ids: staging is not attachment, a new draft version,
  an approved publication preview or a public photo endpoint.

value and cannot replace raw-token authentication at future adapters. Existing
server startup does not import/migrate/expose this staging service automatically.

maintenance exists. A process crash can leave a private orphan or pending row.

restore acceptance is claimed. The OS decoder sandbox, authenticated bounded upload,
photo attachment/ordered preview/new consent, public projection and admin remain
separate delivery gates.

No local project execution: file preparation/static AST and registry inspection
only; runtime/build/browser checks ran in GitHub Actions. No VPS, service/Caddy,
real database/key, main branch, release or public application was changed. The
prior [single-publisher Pages setting](ci-pages.md#remaining-single-publisher-configuration-gate)

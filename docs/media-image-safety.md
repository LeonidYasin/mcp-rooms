# M2a — изолированный контракт нормализации фотографий

## Что добавлено

`media_image.normalize_photo(bytes, declared_type)` — внутренний, необязательный,
синхронный преобразователь без путей, URL, сети и файловой записи. JPEG/PNG по точному
MIME + сигнатуре + определённому декодером формату. GIF/SVG/TIFF/EPS/WebP пока запрещены;
WebP можно добавить отдельным проверенным изменением. APNG с несколькими кадрами запрещён.

Фиксированные лимиты: вход 8 MiB, 12 млн пикселей, сторона 6000 px, выход JPEG не более
1600 px по стороне без увеличения и 2 MiB. Проверки до load, verify и повторное открытие,
полный decode, применение EXIF orientation, уменьшение, белый фон для alpha, новый RGB
canvas. EXIF/XMP/ICC/comment/PNG text не передаются; результат SHA-256 относится к новым
JPEG bytes, а не оригиналу и не является opaque media_id или доказательством владения.
Не гарантировать одинаковый хеш между версиями кодека и не использовать как secret.

Преобразование не подтверждает подлинность фото, отсутствие скрытых данных в пикселях,
вредоносности, дефектов вещи или личных данных на самом изображении. Метаданные удаляются,
но человек всё равно проверяет видимый кадр. Не подменять реальные фотографии AI-картинкой.

## Зависимость и совместимость

Pillow 13.0.0, MIT-CMU, необязательный extra `.[media]`, Python >=3.11. Основной rooms/core
по-прежнему Python >=3.10 без Pillow. На 3.10 media extra не совместим с resolver;
не обходить это установкой `--ignore-requires-python`. CI3.10 проверяет core и пропускает
модуль synthetic media fixtures; CI3.11–3.13 явно устанавливает media и импортирует его,
так что отсутствие зависимости не превращается в скрытое успешное прохождение media gate.

Источники: [PyPI Pillow13](https://pypi.org/project/pillow/13.0.0/),
[Pillow security](https://pillow.readthedocs.io/en/stable/handbook/security.html),
[EXIF transpose](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html).
Pin версии — не полный dependency hash lock и не аудит нативных кодеков.

## Нельзя открывать публичную загрузку на основании этого коммита

- Транспорт обязан ограничить поток ещё ДО сборки bytes; текущая функция получает уже буфер.
- Нужен отдельный worker с OS CPU/RAM/timeout, ограничением параллелизма/очереди и
  уничтожением после timeout. Функция сама НЕ sandbox и не hard RAM bound; стандартные
  Pillow bomb/PNG text guards сохраняются. Warning filters — ещё причина изоляции worker.
- Нужны authenticated ownership, квоты на пользователя/диск, приватный staging,
  непрозрачный media_id, атомарный manifest/ссылки, отказ от symlink/path traversal,
  удаление сирот и сроков, retention и восстановление. Ничего этого здесь не имитируется.
- Публичная раздача только готового нормализованного объекта, без оригинала и произвольного
  пути, с безопасными headers; правила авторизации для черновика/витрины раздельны.
- DraftStore всё ещё отвергает media_ids. Старые private publication intents содержат
  media_ready=false и не могут стать согласием на будущую публикацию с фотографиями.

## Проверки

Только синтетические картинки в GitHub CI: корректный JPEG/PNG, digest/размеры,
alpha на белом, EXIF orientation без приватной метадаты, PNG text, truncation/corruption,
MIME spoofing, APNG, ограничение входа/пикселей/стороны/выхода и bomb guard.
CI evidence фиксируется отдельно по точному SHA. Локальный проект и VPS не запускаются.

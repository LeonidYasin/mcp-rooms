# Позиционирование: люди и агенты, одна площадка

## Короткая формулировка

MCP-first площадка «Хочу / Предлагаю»: человек работает через web, агент через MCP,
оба — с одними объявлениями и правилами. Категории/география помогают находить вещи
и услуги; регистрация не ограничена одним городом. Поездки/доставка — поздний этап,
не готовые функции и не обещание, что уже работает такси.

Публичное имя репозитория пока `mcp-rooms`, без переименования пакета/URL/сервиса:
комнаты — реализованная основа, marketplace — текущее развитие, а не забытый эксперимент.

**Предлагаемое поле GitHub About:**

> Building an MCP-first marketplace connecting people and opportunities through their AI chats: goods, services, jobs, talent, projects, startups and investors. Shared rooms and SQLite core; public web marketplace in development. MIT.

Попытка обновить About через MCP получила GitHub HTTP 403: текущий токен не может
редактировать repository metadata. Поэтому поле About **не объявляется обновлённым**.
README и pyproject description меняются в рабочей ветке; default main не переписывается
этим коммитом. Владелец может изменить About в GitHub вручную (gear рядом с About) или
использовать предложенный выше текст. Владелец выбрал ручное обновление; повторные
попытки расширить доступ для этой задачи не нужны. Не передавать токен/пароль в чат и не
расширять права автоматически. Homepage/topics не менялись.

## Рынок возможностей — не только доска вещей

Долгосрочная задумка: находить людей, предложения и возможности прямо из привычного
личного чата с LLM. Вещи и услуги, работа и поиск специалистов, команды и проекты,
стартапы и знакомства с инвесторами — разные домены одной площадки, а не отдельные
обязательные MCP-коннекторы. Агент помогает сформулировать «хочу / предлагаю», но не
публикует личный чат или предполагаемый интерес без явного решения пользователя.

[Карта возможностей и границы MVP](opportunity-model.md) отделяет этот замысел от
готового кода. Для About слово Building принципиально: перечисление не означает,
что вакансии, инвестиции или публичный marketplace уже запущены.

## Внутренний товар не равен лицу бренда

Б/у унитаз, снятый и помытый, остаётся реальным предметом для функциональной проверки.
Практический сценарий ценен: состояние/комплект, размеры/фото, самовывоз и приватный
отклик. Но делать этот предмет единственным публичным hero launch я не рекомендую:
он способен отвлечь обсуждение от возможностей продукта. Это редакционное решение,
не доказанная маркетинговая статистика и не стигма к категории сантехники.

Не удалять реальный use case и не выдумывать более привлекательную успешную продажу.
Первый технический тест и первый публичный показ — разные этапы. Публичный hero товар
ещё не выбран; нужен настоящий владелец/реальные фото/условия/согласие, а не AI-объект.
Для демонстрации широты достаточно выбранной обычной вещи и реальной услуги, без
фейковых продавцов/отзывов/заказов. Демо данные допустимы только с явной маркировкой.

Технический тест планируется закрытым по доступу, но документация в этом GitHub
репозитории публичная: не называть ветку или этот файл приватными, не добавлять сюда
контакты, домашний адрес, личные переписки или реальные ключи.

## Честные формулировки готовности

- Можно: «alpha», «MCP-first marketplace in development», «rooms accepted in an earlier
  controlled pilot», «private draft core tested in CI» с exact SHA evidence.
- Нельзя пока: «работающий Авито для агентов», «любой уже может продать», «проверенные
  продавцы», «защищённая оплата», «тысячи объявлений», «сделка состоялась».
- Ссылаться на рабочую ветку/PR, когда на main ещё scaffold. Новое About не означает
  merge, публичный web endpoint, постоянный хостинг, auth/abuse или production approval.

Следующий публичный рассказ строится вокруг проверенного пути: человек создаёт
объявление → агент помогает уточнить → владелец видит именно эту версию → явно
публикует → другой человек/агент находит и отправляет приватный отклик. Показывать
только действительно реализованные шаги. До этой приёмки — описание разработки.

# Web Market: актуальное направление

По уточнению владельца: общая площадка для всех, не сервис одного населённого пункта.
Первый тест — попытка продажи настоящей вещи. Основные сегменты: C2C вещи/услуги и
поездки/доставка. Прежняя B2B-автоматизация остаётся лишь возможной категорией, не фокусом.

## Порядок реализации

1. Подробная [mindmap](product-mindmap.md), [граф компонентов и данных](architecture-graph.md),
   [отдельный admin MCP](admin-mcp-design.md), [приёмка первой продажи](first-sale-acceptance.md).
2. Listing contract и визуальный прототип; не изменять установленные room API/DB.
3. Аддитивные categories/listings/media миграции, owner/scopes/CAS/idempotency.
4. Современные адаптивные карточки, форма/фото/preview, публичная opt-in проекция.
5. Пользовательские MCP и web над одним сервисным слоем; отдельная web session.
6. Отдельный admin вход, минимум диагностика/модерация/audit до публичного пилота.
7. Безопасный отклик/приватные переговоры, один реальный предмет, независимый покупатель.
8. Сообщества/категории/подписки, затем структурированные заказы поездок/доставки.

## Инварианты

- География — фильтр, а не допуск; варианты pickup/shipping/online без навязанной страны.
- Человек без MCP может читать и публиковать через web; профиль/email/телефон не обязательны.
- Категория ≠ комната ≠ объявление ≠ заказ. Отдельная долговременная сущность объявления.
- room close не удаляет объявление; текущие 24h сообщения не становятся вечным архивом.
- Старые enrolled-only комнаты не раскрываются интернету и не становятся приватными чатами.
- Public allowlist projection; не контакты/домашние адреса/ключи/скрытые заметки в HTML.
- Однозначные consent draft→publish, версия CAS, повторяемые запросы без дублей.
- Реальные фото для реальной вещи; no fake reviews/sales/urgency, demo маркировать.
- Web безопасная revocable HttpOnly/Secure/SameSite session, CSRF; не Bearer в frontend/URL.
- Медиа: проверка decode/re-encode/EXIF/quota, не arbitrary URL fetch и не хранение base64 в SQLite.
- Отдельный admin MCP, отдельные полномочия, audit/prepare-confirm для риска. Не remote shell.
- Embeddings/LLM optional provider-independent; базовый поиск SQLite/FTS5 при наличии.
- Поездки: quote и транзакционное назначение одного исполнителя; адреса только сторонам,
  реальная доступность, проверка исполнителей и применимых правовых требований.

## Состояние

Ветка alpha; TEST закрыт. Восемь rooms_* существуют. Listing contract/статический макет
начаты отдельно. Каталог/формы/загрузка фото/public API/admin MCP/заказы ещё не включены.
Подробности и матрица состояния в mindmap. Никакого merge/release/production/VPS изменения
самим коммитом; прежние сервисы и БД остаются без изменений.
